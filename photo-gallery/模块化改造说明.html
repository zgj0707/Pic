Pic 模块化改造说明

壳层 + 内容层分离 · 减少重新打包次数 · v2.4.0

改造前 vs 改造后

改造前（一体化打包） 改造后（壳 + 内容分离）
UI、9个IPC模块、服务、数据库全部打进 asar UI、IPC、服务打包为 modules/app.js 外置
改任何一处都要重新打包整个 exe 改 UI/逻辑只需替换 modules/ 目录
壳（main.ts 57KB）与业务代码耦合 壳（main.ts 5KB）只负责加载模块和创建窗口

新的目录结构

位置内容更新方式
exe 同级 modules/
或 resources/modules		 app.js（业务逻辑）
renderer/index.html（界面）
modules.json（清单）		 热更新 · 替换文件即可
asar 内 main.js（壳层引导）
preload.js（API 桥）		 需重新打包（很少发生）
node_modules sharp / exiftool / sql.js 等原生依赖 随 Electron 升级才变

日常更新工作流

场景 1：改界面 / 改业务逻辑（最常见）

  • 改完代码后运行 npm run build
  • 把 dist-app/content/ 里的内容复制到 exe 同级的 modules/ 目录
  • 重启应用，新逻辑生效 无需重新打包 exe

场景 2：加新功能模块

  • 在 electron/content/index.ts 注册新 IPC
  • 重新构建内容层，更新 modules.json 版本号
  • 分发新的 modules/ 文件即可

场景 3：升级 Electron / 原生依赖（极少）

  • 此时才需要 npm run build:win 重新打包 exe
💡 便携版更新方式：把新的 modules 文件夹放到 Pic-portable.exe 旁边，启动时优先加载 exe 同目录的版本。

技术要点

  • 模块接口契约：内容层导出 init / registerIpc / getRendererPath / onWindowCreated / onQuit / syncTagsToExif，壳层只调接口不关心实现。
  • 依赖注入：壳层把 app / BrowserWindow / mainWindow 引用 / 路径信息 通过 ctx 传给内容层。
  • esbuild 打包：内容层打包为单一 CJS 文件（62KB），仅 external electron 和原生依赖，运行时通过 module.paths 增强解析 asar 内的 node_modules。
  • 数据库路径兼容：sql.js 的 wasm 定位增加 resources 候选路径，适配外部模块加载场景。

验证结果

  • TypeScript 类型检查：零错误
  • 壳层 main.js：57KB → 5KB
  • 内容层 app.js：62KB 单文件，66/66 IPC 通道注册成功
  • 模块冒烟测试：84/84 检查通过
  • 单元测试：77/77 通过
  • electron-builder 打包：resources/modules 布局正确
