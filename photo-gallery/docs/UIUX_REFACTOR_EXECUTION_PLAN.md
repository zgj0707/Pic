# Pic 拍摄前样片策划重构执行方案

> 当前技术基线：Pic 3.3.0
> 下一目标版本：Pic 3.4.0
> 核心用户：在拍摄前从互联网和本地收集样片、整理视觉方向并制作拍摄方案的摄影师

## 1. 产品定位

Pic 不是成片交付工具，也不以模特或客户收片为核心场景。它是一套拍摄前参考素材工作台，用于把分散在互联网和本地的样片整理为可执行的拍摄计划。

核心流程：

    建立拍摄项目
    → 收集参考样片
    → 分类筛选
    → 编排灵感板
    → 制作拍摄清单
    → 导出拍摄方案

必须达到的体验目标：

- 用户始终知道当前拍摄项目、素材来源和准备进度。
- 从网页或本地保存参考图时，自动进入当前项目并保留来源信息。
- 可按姿势、构图、灯光、场景、服装、妆发、色彩和镜头等维度整理样片。
- 临时选中、保留/淘汰、灵感板和拍摄清单是不同概念，不混用状态。
- 灵感板支持持久排序、分组、比较和备注。
- 最终输出是 Moodboard、参考图册和 Shot List，不是客户成片交付目录。

## 2. 执行前提

1. 保留当前工作区和提交历史，不使用 git reset --hard、git checkout -- 或其他覆盖用户修改的操作。
2. 当前 3.3.0 已实现项目工作台、网页素材浏览器、初筛、持久精选、对比和一套错误方向的“交付”流程；后续采用渐进式重命名和替换，不一次性推倒重写。
3. 保留 Electron + 原生 JavaScript 架构，本轮不迁移 React、Vue、Svelte 或数据库框架。
4. 每个阶段只完成本阶段目标；测试通过后独立提交。
5. 不删除用户数据库中的旧字段或旧记录。delivered_at 可停止使用，但迁移必须继续兼容已有数据库。
6. 只有需要 portable 验证的阶段才递增版本并重新打包；最终发布阶段必须同步版本、公告和 portable。
7. 默认只提交源码，不提交或上传 portable 文件。

当前验证基线：

- npm.cmd test：103 个测试通过。
- npm.cmd run lint：允许既有 12 条 any 警告，不允许新增错误。
- 当前 portable：dist-pkg/Pic-3.3.0-portable.exe。

## 3. 产品信息架构

### 3.1 项目工作区

- 项目简报
  - 项目名称、拍摄主题、日期、地点、人物和目标风格。
  - 造型、器材、场景和其他准备备注。
- 素材库
  - 网页采集。
  - 本地文件和文件夹导入。
  - 收件箱、全部样片、未分类、已保留、已淘汰。
- 灵感板
  - 有顺序、可持久化的参考图集合。
  - 可按姿势、灯光、造型、场景或自定义章节分组。
  - 支持 2–4 张并排比较、排序和逐图备注。
- 拍摄清单
  - 从灵感板生成具体拍摄项。
  - 每项包含参考图、拍摄意图、动作/构图说明、灯光/器材提示和顺序。
- 方案导出
  - Moodboard PDF。
  - Shot List PDF。
  - 可选的参考图片副本包。

### 3.2 辅助空间

- 素材浏览器、下载记录、回收站、设置、更新公告和关于。
- 辅助空间不能成为主流程终点，必须一键返回当前拍摄项目。

### 3.3 统一术语

| 当前术语 | 新术语 | 处理方式 |
| --- | --- | --- |
| 照片 | 参考样片 | UI 文案渐进替换，底层 photos 表暂不改名 |
| 精选篮 | 灵感板 | 复用 project_selections 和现有排序能力 |
| 交付候选 | 已加入灵感板 | 替换所有用户可见文案 |
| 交付 | 拍摄方案 | 重做页面目标和操作 |
| 联系表 PDF | Moodboard PDF | 调整版式和信息内容 |
| delivered_at | 弃用字段 | 保留兼容，不再作为产品状态写入 |

## 4. 状态和数据原则

- selectedPhotoIds：当前页面临时批量选择。
- review_state：参考样片的未处理、保留、淘汰状态。
- project_selections：灵感板中的持久条目和顺序。
- 拍摄清单使用独立业务状态，不复用评级、初筛状态或 delivered_at。
- localStorage 只保存界面偏好；项目、来源、灵感板、备注和拍摄清单进入数据库。
- 所有数据库迁移先检查 PRAGMA table_info 或表是否存在，保持幂等。
- 删除进入回收站时保留灵感板和拍摄清单关系；永久删除前必须清理或明确标记关联。

建议的数据扩展在对应阶段实施，不提前一次性加入：

- 阶段 2：为参考样片增加 source_url、source_domain、source_type、source_note。
- 阶段 3：新增 project_shots，记录项目、参考图、顺序、章节、标题、拍摄说明、器材/灯光提示和时间戳。
- 字段名称在实施前必须结合现有数据库查询和 IPC 再确认；本计划不授权无迁移测试的直接建表。

## 5. 四阶段实施计划

### 阶段 1：纠正产品语义与项目简报

目标：让现有 3.3.0 界面明确服务于拍摄前准备，并停止继续暴露客户交付语义。

操作：

- 将“照片”“精选篮”“交付候选”“交付”等主流程文案替换为“参考样片”“灵感板”“拍摄方案”。
- 将现有交付入口暂时改造成“拍摄方案”入口；在新方案功能完成前，不继续写入 delivered_at。
- 保留现有导出代码以便后续复用，但从主流程中移除“客户文件夹”和“交付完成”等含义。
- 扩展项目简报界面，先复用现有项目名称、描述和拍摄日期；新增字段前先确认数据库迁移范围。
- 更新空状态和导航说明，让用户从启动页清楚看到“建立项目—收集样片—制作方案”的路径。
- 不改浏览器采集、数据库结构和整个布局。

完成标准：所有核心页面不再把软件描述为成片交付工具；已有项目、导入、初筛、灵感板和对比功能保持可用。

建议提交：refactor(product): align workflow with pre-shoot planning

### 阶段 2：样片采集、来源与分类

目标：让互联网样片从“下载文件”变成有来源、有用途的项目参考素材。

操作：

- 网页保存和本地导入都明确进入当前项目；没有项目时引导先创建或选择项目。
- 为网页素材保存来源 URL、域名、采集时间和可选备注；本地文件记录来源类型。
- 在详情面板显示来源并提供“打开原网页”操作。
- 建立适合拍摄准备的分类维度：姿势、构图、灯光、场景、服装、妆发、色彩、镜头、自定义。
- 复用现有标签和筛选能力，先补预设和组合筛选，不重写标签系统。
- 保留键盘初筛，将语义解释为“是否纳入本次拍摄参考”。
- 增加旧数据库和无来源历史照片的迁移测试；历史照片来源显示为“本地/未知”。

完成标准：从网页保存一张样片后，可以在当前项目中看到原始来源，并能按拍摄维度分类和重新找到。

建议提交：feat(reference): add source-aware sample collection

### 阶段 3：灵感板与拍摄清单

目标：把筛选出的样片转化为现场可以执行的拍摄顺序。

操作：

- 将现有 project_selections 和排序 UI 正式定义为灵感板。
- 灵感板支持章节/分组、拖动排序和逐图备注；分组优先使用增量字段或关联表，不重建原表。
- 保留并排对比，补充“加入章节”“拍摄意图”和“用这张图参考什么”等操作。
- 新增独立的拍摄清单数据和 IPC。
- 支持从灵感板生成拍摄项，并记录：标题、参考图、动作/构图说明、灯光/器材提示、顺序。
- 参考图进入回收站时显示警告但不静默删除拍摄项；永久删除时保持关系一致性。
- 不在本阶段重做所有 UI，也不加入日程、团队协作或云同步。

完成标准：用户可把不同来源的样片编排成分章节的灵感板，并生成有明确顺序和说明的 Shot List。

建议提交：feat(planning): turn inspiration boards into shot lists

### 阶段 4：方案导出、质量收尾与 3.4.0 portable

目标：生成拍摄前可查看、打印或分享的方案，并形成稳定的 3.4.0 版本。

操作：

- 将现有 delivery.js 渐进改造成方案导出模块，必要时改名为 planningExport.js，但不同时迁移框架。
- 支持 Moodboard PDF：项目简报、章节、参考图、来源和逐图备注。
- 支持 Shot List PDF：拍摄顺序、缩略图、动作/构图说明、灯光/器材提示和现场勾选区。
- 可选生成参考图片副本包；保留原始文件名和路径，副本命名只用于方案包内部。
- 导出前显示目标目录、页数/项目数、缺失文件和回收站警告；部分失败必须逐项报告。
- 使用新的方案导出时间或导出记录；不再写入 delivered_at。
- 完成键盘、焦点、对比度、100%/125%/150% 缩放和 prefers-reduced-motion 检查。
- 保留分页和虚拟滚动，验证 1000、5000、10000 张参考样片项目；灵感板更新不得重绘整个网格。
- 版本统一递增到 3.4.0，更新公告并重新生成 portable。

完成标准：用户能从拍摄项目生成可用的 Moodboard 和 Shot List；10k 样片项目核心操作可用；3.4.0 portable 验证通过。

建议提交：release: publish Pic 3.4.0 pre-shoot workflow

## 6. 文件职责

- public/index.html：语义结构、工作区、模态框和脚本入口。
- public/js/state.js：共享 UI 状态和事件总线。
- public/js/navigation.js：项目工作区与辅助空间切换。
- public/js/projects.js：项目 CRUD 和项目简报。
- public/js/import.js：本地参考样片导入。
- public/js/culling.js：参考样片初筛和快捷键。
- public/js/selectionTray.js：灵感板持久状态与排序。
- public/js/compare.js：参考样片并排比较。
- public/js/delivery.js：阶段 1–3 期间保留兼容；阶段 4 改造为方案导出。
- public/js/grid.js：参考样片网格、虚拟滚动和单元格交互。
- public/js/lightbox.js：单张查看、缩放、旋转和参考备注入口。
- Electron IPC/服务：按来源、灵感板、拍摄清单和导出职责拆分，不建立万能处理器。

## 7. 测试清单

### 自动测试

- 旧项目和旧照片数据库可幂等升级。
- 无来源历史照片仍可显示、筛选和加入灵感板。
- 网页采集记录进入当前项目并保存来源。
- review_state 与评级互不覆盖。
- 灵感板新增、去重、删除、重排、分组和项目隔离。
- 删除、恢复、永久删除与灵感板/拍摄清单关系一致。
- 拍摄清单新增、编辑、重排和持久化。
- Moodboard/Shot List 部分失败时返回准确的成功、跳过和失败项目。
- 灵感板更新不调用整个参考样片网格重绘。

### 手工验证

1. 从 3.1.x、3.2.x 和 3.3.0 数据库升级。
2. 新建拍摄项目并填写简报。
3. 从素材浏览器保存样片，确认来源 URL 和当前项目正确。
4. 导入本地样片并按姿势、灯光、场景等维度分类。
5. 用键盘完成筛选并加入灵感板。
6. 跨筛选补充灵感板，分组、排序、比较并填写参考备注。
7. 生成拍摄清单并重启应用，确认顺序和说明保持。
8. 导出 Moodboard PDF 和 Shot List PDF，确认缺失文件不会被误报为成功。
9. 删除和恢复一张已引用样片，确认灵感板与拍摄清单关系正确。
10. 在 100%、125%、150% 缩放和 1000/5000/10000 张样片下检查核心流程。
11. 从没有外部 modules 目录的空文件夹启动最终 portable。

## 8. 版本、打包与提交规则

1. 每个阶段先确认工作区状态，保留所有不属于本阶段的修改。
2. 每阶段完成后执行与风险相称的测试、lint 和构建，并独立提交。
3. 阶段 1–3 默认不生成 portable；若某阶段必须验证 portable，则先递增版本并同步：
   - package.json
   - package-lock.json
   - electron/content/index.ts
   - electron/changelog.json
   - CHANGELOG.md
4. 阶段 4 必须执行：
   - npm.cmd test
   - npm.cmd run lint
   - npm.cmd run build:win
5. 核对 dist-pkg/Pic-3.4.0-portable.exe 的文件名、大小和修改时间。
6. portable 不提交、不上传，除非用户明确要求。

## 9. 禁止事项

- 不得重新引入“客户交付”“成片交付”“模特收片”作为主流程。
- 不得删除或重建用户数据库，也不得为了改字段名破坏旧数据。
- 不得继续把 delivered_at 当作拍摄方案状态。
- 不得把临时批量选择、初筛结论、灵感板和拍摄清单合并为同一状态。
- 不得同时迁移框架、重写数据库和重做全部 UI。
- 不得删除虚拟滚动并改为 10k 参考样片完整 DOM 渲染。
- 不得让网页下载脱离当前项目或丢失来源。
- 不得只靠图标表达新建项目、采集样片、加入灵感板、制作方案等核心动作。

## 10. 最终验收场景

使用真实旧数据库和至少 1000 张互联网/本地参考样片完成：

    创建拍摄项目
    → 填写拍摄简报
    → 从网页和本地收集参考样片
    → 按拍摄维度分类与筛选
    → 编排分章节灵感板
    → 生成并调整 Shot List
    → 导出 Moodboard 与拍摄清单

整个流程不得出现客户成片交付语义，不修改参考图原始文件，不丢失网页来源、灵感板顺序或拍摄说明。全部通过后发布 Pic 3.4.0。
